# AMO 结构保持算子说明（论文 / 示意图撰写用）

本文档与 PlatEMO 工程内实现一致，对应源码目录：`A-amos/`（`SegmentBasedCrossover.m`、`OrderPreservingMutation.m`、`func/OperatorAMO.m`、`OrderSegmentRepair.m` 等）。可直接用于撰写方法章节、绘制示意图、做消融说明。

---

## 1. 编码与约束（Chromosome）

- **决策向量长度**：`varDim = 2n + (m − 1)`。  
  - `n`：商家数量；客户点与商家一一对应，编号为 `n+1 … 2n`（客户 `j` 对应商家 `j`）。  
  - `m`：无人机（路径段）数量；用 **`0` 作为段间分隔符**，共 **`m − 1` 个 0**。
- **语义**：整条染色体是 `m` 条子路径的拼接；第 `k` 段表示第 `k` 架无人机的访问序列（不含 0）。
- **硬约束（实现中反复修复）**  
  1. 全体非零基因恰为 `1 … 2n` 各出现一次（排列 + 分段）。  
  2. 对任意商家 `s ∈ {1,…,n}`，其在序列中的位置 **早于** 对应客户 `s+n`。  
  3. 每个段内应尽量保持 **商家–客户成对完整**（不把同一对拆到两个段）；交叉/变异后由 `repairSegments` / `OrderSegmentRepair` 等兜底。  
  4. 首尾不为 `0`；段长过短（如段内不足一对）时由 `repairSegmentSizes` 类逻辑调整。

### 1.1 文本槽位表示（【】，不依赖 TikZ）

论文或讲稿里若不便画条形图，可用 **每个【】表示染色体上的一个基因槽位**（与实现里 `varDim` 向量的一格一一对应）；**`0` 为段间分隔**，两侧留空格更易读。

**示例（`n = 4`，`m = 2`，仅 1 个 `0`）**：一条合法染色体可写成一行：

```text
【1】【2】【5】【6】 0 【3】【4】【7】【8】
```

读法：第一段为子路径 1，基因顺序为商家 1、商家 2、客户 5、客户 6（满足 1 在 5 前、2 在 6 前）；`0` 后为第二段子路径，顺序为 3、4、7、8（同理 3 在 7 前、4 在 8 前）。**同一组 `1…8` 与 1 个 `0` 还可排成其它顺序**，只要全局仍为排列、且每对商家早于其客户即可，例如与源码示意图中父代 `P_1` 一致的另一种排法：

```text
【1】【5】【2】【6】 0 【3】【7】【4】【8】
```

第二父代常写作（与 `AMO_operator_encoding_diagrams_tikz.tex` 中示例一致）：

```text
【2】【6】【1】【5】 0 【4】【8】【3】【7】
```

交叉/变异段落若只写“左段 / 右段 / 切点一侧”，用上述三行之一作起点即可，无需再画基因方块。

**示意图（可选）**：若期刊仍要配图，再画水平基因带：用竖线或灰色块标 `0`，每段内用同色标 `(m_i, c_i)`。**日常描述优先用本节的【】一行式。**

## 2. 总体流程：`OperatorAMO`

对种群中每个父代个体 **生成 1 个子代**：

1. 以概率 **`pc`**（默认 0.5）执行 **交叉**；否则执行 **变异**。  
2. 交叉：`SegmentBasedCrossover(parent1, parent2, n, m, varDim)`。  
   - 第二父代可为聚类交配给出的 `P2(i)`，或在种群中随机选与 `i` 不同的个体。  
3. 变异：`OrderPreservingMutation(parent1, m, varDim, n, er)`。  
   - **`er`**：大步长变异（T4）的概率；其余时间在 T1–T3 间均匀随机。  
4. 统一调用 **`OrderSegmentRepair`**，再截断/补零到 `varDim`，最后 **`Problem.Evaluation`**。

**示意图建议（Fig. 算子管道）**：`父代 → [交叉 | 变异] → OrderSegmentRepair → 评估`。

---

## 3. 交叉入口：`SegmentBasedCrossover`

### 3.1 三种策略的随机选择（概率）

```text
若 r ~ U(0,1) < 0.4      → PTC（Position Tracking Crossover）
否则若 r < 0.7           → PPC（Pair Priority Crossover）
否则                     → OPC（Order Preserving Crossover）
```

即 **PTC : PPC : OPC = 0.4 : 0.3 : 0.3**。

> 注：文件中有 `persistent crossoverWeights` 等注释，当前实现为上述固定阈值随机，**未**启用自适应轮盘权重。

### 3.2 后处理

- 长度对齐到 `varDim`，**首尾去 0**（`ensureNoZeroAtEnds`）。  
- **克隆防御**：若子代与 `parent1` 或 `parent2` **完全相同**，调用 **`SegmentBasedCrossover_forceDisrupt`**：在段间或段内交换/重插完整的商家–客户对，打破完全相同继承。

## 4. PTC：位置追踪交叉（Position Tracking Crossover）

**设计目的**：在保留父代 1 前缀的前提下，用父代 2 的“剩余基因”按序填充后缀，并维持 **商家先于其客户** 的全局顺序。

**步骤概要**：

1. **合法性检查**：两父代须满足 `isValid`（每个 `s` 在 `s+n` 之前）。否则退回 `parent1`。  
2. **位置映射**：为每个基因 `1…2n` 记录其在染色体中的下标 `pos_map(gene)`。  
3. **安全切点 `k`**：在 `1 … len−1` 中筛选 **同时对两父代安全** 的位置：  
   - 安全定义：不存在一对 `(s, s+n)` 使得 `pos(s) < k < pos(s+n)`（即切点不把同一对劈成“商家在左段、客户在右段”）。  
   - 若无安全切点，退回 `parent1`。  
4. **构造子代**：  
   - `offspring(1:k) = parent1(1:k)`。  
   - 从 `parent2` 从左到右扫描，向 `offspring(k+1:)` 填入 **尚未使用** 的基因：  
     - `0`：可直接填入；  
     - 商家 `1…n`：可直接填入；  
     - 客户 `n+1…2n`：仅当对应商家 **已在已填集合** 中时才填入（保证前缀已出现商家）。  
5. **修复链**：`repairSolution` →（必要时）`repairOrder` → `repairSegments`。

**示意图建议**：两条父代序列，竖线在共同认可的 `k` 处；左段复制 P1，右段用 P2 扫描填充，用虚线标出“客户延迟出现直到其商家已出现”。

---

## 5. PPC：对优先级交叉（Pair Priority Crossover）

**设计目的**：由两父代推导 **商家优先级**，合并后决定商家在子代中的相对顺序，再插入客户。

**优先级定义**：对父代 `p`，商家 `s` 的优先级为其 **首次出现位置**（越靠前优先级越高，数值越小）。

**步骤概要**：

1. `priority1(s) = first_index(s, parent1)`，`priority2` 同理。  
2. **合并**：`merged(s) = min(priority1(s), priority2(s))`（取两父代中更早出现者作为更强优先级）。  
3. 按 `merged` **升序**得到商家顺序 `sorted_merchants`。  
4. **构图式填充**（初稿）：  
   - 先将 `sorted_merchants` 依次写入子代前面连续位置；  
   - 再对每个商家 `s`，在全局序列中从其位置向右扫描，把 **第一个仍为 0 的位置** 替换为客户 `s+n`。  
5. **修复链**：同 PTC — `repairSolution` → `repairOrder` → `repairSegments`。

**与 PTC 的差异（写论文时可强调）**：PPC 显式在 **商家层** 融合双亲的“先后信息”（min 取优），而不是基于切点的基因串重组。

---

## 6. OPC：顺序保持交叉（Order Preserving Crossover）

**设计目的**：融合两父代的 **商家遍历顺序**，保持某种“顺序继承”，再按与 PPC 相同的方式插入客户。

**步骤概要**：

1. `order1`：扫描 `parent1`，提取商家编号序列并 **去重**（保持首次出现顺序）。`order2` 同理。  
2. **融合**：随机 `fusion_point ∈ [1, |order1|]`，  
   `fused = [order1(1:fusion_point), order2(fusion_point+1:end)]`，再 `unique(...,'stable')`。  
3. **补全**：将 `order1 ∪ order2` 中尚未出现在 `fused` 的商家按 `setdiff` 接到末尾，保证 `1…n` 齐全。  
4. 若 `fused` 与 `order1` 完全相同，**随机交换** `fused` 中两个商家位置，避免与单亲顺序完全一致。  
5. 与 PPC 相同：**先顺次写商家，再在各自商家后找第一个 0 填客户**。  
6. **修复链**：同上。

**与 PPC 的差异**：OPC 的商家顺序来自 **顺序向量的切点融合**，而非 `min(位置)` 的逐基因竞争。

## 7. 交叉内的修复子程序（理解示意图时的“兜底框”）

| 子程序 | 作用（直觉） |
|--------|----------------|
| `repairSolution` | 补齐缺失基因、处理重复位、把 0 的个数调到 `m−1`、长度对齐 `varDim`、首尾非 0、段长启发式修复。 |
| `repairOrder` | 若出现 `pos(s) > pos(s+n)`，把商家剪贴到客户之前。 |
| `repairSegments` | 若某对客户被分到两段，把客户段迁移到商家所在段并插在商家后。 |
| `repairSegmentSizes` | 避免某段长度过短（非偶数/不足一对）等病态分段，必要时移动 `0`。 |

论文中可画 **“交叉核心 → 修复流水线”** 一层框图，表明可行性由修复保证。

## 8. 变异：`OrderPreservingMutation`

**前提**：输入个体须已有 **恰好 `m−1` 个 0**；否则函数直接返回（或仅警告），不变异。

### 8.1 策略选择概率

- 以概率 **`explorationRate`（即 OperatorAMO 的 `er`）** 执行 **T4（大步长）**。  
- 否则在 **T1、T2、T3** 上以 **各 `(1−er)/3`** 均匀随机。

### 8.2 T1：段内商家前移（实现为移到段首）

- 随机选一段含商家的段，再随机选一个商家；  
- 在该段内 **删除该商家原位置，插入到该段最前端**（客户不随动，故可能改变“商家相对客户”的局部顺序，后续靠 `OrderSegmentRepair` 等约束整体可行）。

**示意图**：同一段内，选中商家基因箭头移到段首。

### 8.3 T2：段内客户后移（实现为移到段末）

- 随机选含客户的段与客户点；  
- **删除原位置，追加到该段末尾**。

### 8.4 T3：移动分隔符 `0`（不撕开完整对）

- 随机选一条可移动的段间 `0`（相邻段非空等条件）；  
- 随机方向：**向前（深入前一段）** 或 **向后（深入后一段）**。  
- **向前** `traverse_forward`：从前一段尾部向前扫，只在 **商家** 处尝试把 `0` 插到该商家 **之前**，且要求：该商家之后已扫过的客户集合仅来自 **已扫过的商家**（不把未闭合对的客户隔到边界外）。  
- **向后** `traverse_backward`：从后一段头部向后扫，只在 **客户** 处尝试把 `0` 插到该客户 **之后**，且要求：该客户之前已扫过的商家仅来自 **已扫过的客户** 对应商家。  
- 删除旧 `0`、在新位置插入 `0`，并做索引修正与长度对齐。

**示意图**：`0` 在合法“成对边界”上滑动，左右两段任务量改变 → **负载重分配**，步长大于 T1/T2。

### 8.5 T4：跨段迁移完整对（大步长）

- 随机选 **至少含 2 个商家** 的源段；随机选源段中一对 `(m, m+n)`（须同段内均有）。  
- 从源段 **删除** 该对，保持其余相对顺序。  
- 随机选 **另一段** 为目标段，在随机插入位置 **连续插入 `m, m+n`**（商家紧邻其客户）。  
- 重建整条染色体；若长度、`1…2n`  multiset、或任一顺序约束不满足则 **放弃**（返回未改或原逻辑下的不变）。

**与 T3 区别（可写进论文）**：T3 主要移动 **分界 0**；T4 直接 **剪切–粘贴任务对**，改变哪架无人机服务该对，步长通常更大。

### 8.6 变异后处理

- 校正 `0` 的个数与 `varDim`；若子代与父代仍相同，**强制再试 T4**，再失败则尝试 **段内随机交换两对**。

## 9. `OrderSegmentRepair`（算子后统一修复）

在 `OperatorAMO` 中 **每次** 交叉/变异后调用：保证首尾非 0、段内成对结构、段长合理，并与 `varDim` 一致。与交叉内部的 `repairSegments` 系列 **思想一致**，属工程上的二次兜底。

## 10. 论文撰写提示（可直接粘贴扩展）

- **贡献点表述**：针对“商家–客户成对 + 多机分段”编码，提出 **三段式随机交叉（PTC/PPC/OPC）** 与 **四模式结构保持变异（T1–T4）**，并通过 **修复流水线** 保证可行解。  
- **复杂度**：交叉/变异主体为 `O(varDim · n)` 量级扫描（实现以 MATLAB 向量操作为主）；修复可能多轮循环，上界与 `varDim` 相关。  
- **消融建议**：固定 `pc`、`er`，分别将 PTC/PPC/OPC 之一概率设为 1 或关闭 T4，观察 HV/IGD 与收敛曲线。  
- **示意图 / 文本清单**

  2. PTC 安全切点与填充规则（可仅用两行父代 + 一行子代的【】文本）；  
  3. PPC 的 `min(位置)` 融合；  
  4. OPC 的 `order1/order2` 融合；
