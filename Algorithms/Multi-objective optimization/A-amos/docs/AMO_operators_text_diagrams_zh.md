## AMO 算子文本示意（【】+0 分段）——3 交叉 + 4 变异

本文件用于**不画 TikZ**也能清晰表达算子流程：用 `【】` 表示一个基因槽位，用 `0`（两侧留空格）表示段间分隔符。你可以直接照着这里的“前→后”画示意图。

---

### 0. 基本约定（与源码一致）

- **基因集合**：商家为 `1..n`，客户为 `n+1..2n`，且客户 `s+n` 对应商家 `s`。
- **分段**：`m` 段用 `m-1` 个 `0` 分隔；本文件示例用 `m=2`（因此只有 1 个 `0`）。
- **可行性（画图时要保持）**：
  - `1..2n` 各出现一次；`0` 的个数固定为 `m-1`；
  - 对任意 `s`，必须 **商家 `s` 在客户 `s+n` 之前**（全局顺序约束）。

---

### 1. 示例输入（统一用这一组做讲解）

取 `n=4, m=2`，则基因集合为 `1..8`，分隔符为 1 个 `0`。

- 父代 1（P1）：

```text
P1 = 【1】【5】【2】【6】 0 【3】【7】【4】【8】
```

- 父代 2（P2）：

```text
P2 = 【3】【7】【1】【5】 0 【4】【8】【2】【6】
```

---

## 2. 交叉算子（3 个）

### 2.1 PTC：位置追踪交叉（Position Tracking Crossover）

**一句话**：找一个不“劈开成对”的安全切点 `k`；左侧复制 P1，右侧按 P2 扫描补齐，且**客户只有在其商家已出现后才允许写入**。

**(A) 选安全切点 k**

- “安全”的直觉：切点不能把某一对 `(s, s+n)` 切成“左边只有商家、右边才出现客户”（或反过来）。画图时可以用竖虚线标 `k`。
- 用本示例可取 `k=4`（切在 P1 的第 4 个槽位之后），即：

```text
P1 = 【1】【5】【2】【6】 | 0 【3】【7】【4】【8】
```

**(B) 构造子代（示例）**

1) 左半段直接复制 P1 的前 4 个槽位：

```text
Off(1..4) = 【1】【5】【2】【6】
```

2) 从 **P2 从左到右**扫描（`P2 = 【3】【7】【1】【5】 0 【4】【8】【2】【6】`），只处理**尚未出现在子代中**的基因，并遵守“客户须晚于其商家”：
   - `3`（商家）：**填入**；
   - `7`（客户）：其商家 `3` 已在子代中 → **填入**；
   - `1, 5`：左段已复制过，**跳过**；
   - `0`：**填入**；
   - `4`（商家）：**填入**；
   - `8`（客户）：其商家 `4` 已在子代中 → **填入**；
   - `2, 6`：左段已复制过，**跳过**。

得到一个直观的子代示例：

```text
O_PTC = 【1】【5】【2】【6】【3】【7】 0 【4】【8】
```

> 画图提示：PTC 的示意图重点是“左段复制 + 右段扫描填充 + 客户延迟直到商家出现”，以及安全切点竖虚线。

---

### 2.2 PPC：对优先级交叉（Pair Priority Crossover）

**一句话**：在**整条染色体**（含客户与段间 `0`，每个【】占一个槽位）上，为每个商家 `s` 记录**首次出现**的槽位下标；双亲各有一套下标，取 `min` 得合并优先级，再排序商家；最后在子代向量里先顺排商家，再按源码规则把客户塞进“商家右侧第一个仍为 `0` 的槽”，并交给修复整理分段。

**(A) 在完整父代上读“首次出现槽位”（客户、`0` 都占槽位）**

用与 §1 相同的 `P1/P2`，在下方标出槽位编号 `1..9`（`varDim=2n+(m-1)=9`）：

```text
槽位:   1    2    3    4    5    6    7    8    9
P1 = 【1】【5】【2】【6】【0】【3】【7】【4】【8】
P2 = 【3】【7】【1】【5】【0】【4】【8】【2】【6】
```

只看**商家数字** `1..4` 第一次出现在哪一格（**槽位 5** 上的基因是段间 `0`，也占一格；客户 `5..8` 同样各占一格）：

| 商家 `s` | 在 P1 中首次槽位 `pri_1(s)` | 在 P2 中首次槽位 `pri_2(s)` |
|----------|-----------------------------|-----------------------------|
| 1 | 1 | 3 |
| 2 | 3 | 8 |
| 3 | 6 | 1 |
| 4 | 8 | 6 |

（源码里对每位商家执行 `priority(gene)=槽位 i` 的**逐格覆盖**；合法个体中每位商家只出现一次，故数值上等于**首次**槽位。）

**(B) 合并优先级与商家排序（与 `SegmentBasedCrossover.m` 一致）**

- `merged(s) = min(pri_1(s), pri_2(s))` → 本例：`merged = [1, 3, 1, 6]`（对应 `s=1,2,3,4`）。
- MATLAB：`[~, sorted_merchants] = sort(merged_priority)`；**`merged` 相同时按商家编号升序**（向量下标小的在前）→  
  先排 `merged=1` 的商家 `1,3`，再 `merged=3` 的 `2`，再 `merged=6` 的 `4`：  
  `sorted_merchants = [1, 3, 2, 4]`，写成一行即：

```text
商家顺序 = 【1】【3】【2】【4】
```

**(C) 码字与插入客户（与源码一致；这里的 `0` 先是“空位占位”，不是已经画好的段间分隔）**

源码里子代向量一开始是 **`zeros(1, varDim)`**：每个槽位上的 `0` 只表示**还没填**，并不表示“段间分隔已经放在正确位置”。`m=2` 时最终应有 **1 个**真正的段间 `0`，那是 **`repairSolution` 等修复之后** 的事。

1. 先得到长度 9 的全 `0` 串，再按 `sorted_merchants = [1,3,2,4]` 从左起写入商家：

```text
槽位:  1    2    3    4    5    6    7    8    9
      【1】【3】【2】【4】【0】【0】【0】【0】【0】   ← 后 5 格仍是“空位 0”
```

2. 仍按 **`sorted_merchants = [1,3,2,4]` 的顺序**（与源码循环顺序一致）：对每个商家，向右找**第一个还是 0 的槽**，改成其客户 `s+4`：

| 步骤 | 操作 | 结果（只看 5–9 格的变化） |
|------|------|---------------------------|
| 处理商家 1 | 槽 1 右侧第一个 `0` 是槽 5 → 填客户 5 | …【5】【0】【0】【0】【0】 |
| 处理商家 3 | 槽 2 右侧第一个 `0` 是槽 6 → 填客户 7 | …【5】【7】【0】【0】【0】 |
| 处理商家 2 | 槽 3 右侧第一个 `0` 是槽 7 → 填客户 6 | …【5】【7】【6】【0】【0】 |
| 处理商家 4 | 槽 4 右侧第一个 `0` 是槽 8 → 填客户 8 | …【5】【7】【6】【8】【0】 |

填完客户后，**槽 9 仍然是初始占位 `0`**，从未被上述规则改过，所以它会**暂时留在最后**：

```text
O_PPC（填充后、Repair 前）= 【1】【3】【2】【4】【5】【7】【6】【8】【0】
```

这不满足“段间分隔符在两段任务之间、且首尾非 0”等约定，因此**不是**最终染色体，只是 PPC **码字阶段的中间态**。下面按 **`SegmentBasedCrossover.m` 里交叉后的调用顺序**（`repairSolution` →（必要时）`repairOrder` → `repairSegments`）把**本例**一步步画出来；你画示意图时可 **一帧一步**，在槽位上标交换箭头即可。

**起点（PPC 码字刚结束，与上文一致）**

```text
R0 = 【1】【3】【2】【4】【5】【7】【6】【8】【0】
```

---

**步骤 1：`SegmentBasedCrossover_repairSolution`**

- **1a 缺失/重复基因**：本例已含 `1..8` 各一次，**不改**。
- **1b `0` 的个数**：已是 `m−1=1` 个，**不改**。
- **1c `SegmentBasedCrossover_ensureNoZeroAtEnds`**：规定**首尾不能是 `0`**。当前末尾是 `0`，实现里把**最后一个非零基因**与**末位 `0`** 对调（等价于把 `0` 往右“换”到一对点之后）：

```text
R1 = 【1】【3】【2】【4】【5】【7】【6】【0】【8】
```

- **1d `SegmentBasedCrossover_repairSegmentSizes`**：要求每个被 `0` 切开的段**至少 2 个基因**。在 `R1` 里 `0` 在槽 8，**第二段**只有 `【8】` 长度 1。规则：把**最后一个 `0` 与左侧相邻基因**对调，让 `0` 左移、拉长末段：

```text
R2 = 【1】【3】【2】【4】【5】【7】 0 【6】【8】
```

（此时两段长度分别为 6 和 2，都 ≥2。）

---

**步骤 2：`repairOrder`（仅当 `isValid` 为假时调用）**

本例在 `R2` 上已满足每个商家早于其客户，一般**不会再改**；若你画图可画成虚线框“本例跳过”。

---

**步骤 3：`SegmentBasedCrossover_repairSegments`（成对不跨 `0`）**

把 `0` 左右两段看成两个桶。若有**商家**在左段、**对应客户**在右段，就把客户**剪到左段、紧挨该商家后面**（按商家编号 `1..n` 依次处理；源码在 `for` 循环内只改两段元胞，**循环结束**才拼回一条串。下面 **R3/R4 是为画图拆开的中间结果**，与循环执行顺序一致。）

- 处理完商家 **2**（客户 **6** 从右段挪到左段 `【2】` 后）若立刻拼回：

```text
R3 = 【1】【3】【2】【6】【4】【5】【7】 0 【8】
```

- 再处理商家 **4**（客户 **8** 挪到左段 `【4】` 后）拼回；右段已空：

```text
R4 = 【1】【3】【2】【6】【4】【8】【5】【7】 0
```

（再经函数末尾的 **`ensureNoZeroAtEnds` + `repairSegmentSizes`**，消除尾 `0` 与过短段。）

**（重要）**：`SegmentBasedCrossover_repairSegments` 在末尾会再跑一遍 **`ensureNoZeroAtEnds` + `repairSegmentSizes`**。这两步只保证**首尾非 0**与**段长 ≥2**，并不再次检查“客户是否又被 `0` 推到了另一段”。因此，把上面的 `R4` 继续执行这两步，本例会得到下面这个“交叉模块 Repair 后”的结果（它可能仍会出现对跨段的情况，后续由 `OperatorAMO` 的统一修复再兜底）：

```text
R5（交叉模块 Repair 后）= 【1】【3】【2】【6】【4】【8】 0 【5】【7】
```

---

**与 `OperatorAMO` 的关系（建议你画到这一层）**

在 `OperatorAMO` 里，交叉/变异结束后还会调用一次 **`OrderSegmentRepair`**（`OrderSegmentRepair.m`），它会再做一轮：`EnsureNoZeroAtEnds → RepairSegments → RepairSegmentSizes`，把“跨段的客户”再拉回到商家所在段，并重新调 `0` 的位置。

对本例，把 `R5` 继续过一遍 `OrderSegmentRepair`，可以画成下面 3 帧（这是更接近最终输出、也更符合你想画的“成对不跨段”直觉的版本）：

```text
S0 = 【1】【3】【2】【6】【4】【8】 0 【5】【7】          （输入 OrderSegmentRepair）
S1 = 【1】【5】【3】【7】【2】【6】【4】【8】 0            （RepairSegments：把 5/7 拉回段 1，段 2 变空）
S2 = 【1】【5】【3】【7】【2】【6】 0 【4】【8】          （EnsureNoZeroAtEnds + RepairSegmentSizes：把 0 移到两段之间且末段≥2）
```

把这三帧“怎么来的”拆成**可画箭头**的两步（严格对应 `OrderSegmentRepair.m` 的调用顺序）：

- **Step A：`RepairSegments(sol,n,m)`（把跨段客户拉回商家所在段，插在商家后）**
  - 先按 `0` 分段：`S0` 左段为 `【1】【3】【2】【6】【4】【8】`，右段为 `【5】【7】`。
  - 检查每一对 `(s,s+n)`：
    - 对 `s=1`：商家 `1` 在左段、客户 `5` 在右段 → 把 `【5】` 从右段剪掉，插到左段 `【1】` 后。
    - 对 `s=3`：商家 `3` 在左段、客户 `7` 在右段 → 把 `【7】` 从右段剪掉，插到左段 `【3】` 后。
  - 这时右段被清空，拼回序列会变成“左段 + 0 + 空段”，也就是 `S1` 末尾带 `0`：

```text
S1 = 【1】【5】【3】【7】【2】【6】【4】【8】 0
```

- **Step B：`EnsureNoZeroAtEnds → RepairSegmentSizes`（把尾 0 移回段间，并保证末段≥2）**
  - `EnsureNoZeroAtEnds`：末尾是 `0`，就把末位 `0` 与最后一个非零 `【8】` 交换：

```text
T1 = 【1】【5】【3】【7】【2】【6】【4】 0 【8】
```

  - `RepairSegmentSizes`：此时 `0` 把序列切成两段，右段只有 `【8】`（长度 1 < 2），规则是把 `0` 与左边紧邻基因 `【4】` 交换，让 `0` 左移一格，右段变成 `【4】【8】`：

```text
S2 = 【1】【5】【3】【7】【2】【6】 0 【4】【8】
```

**画论文图时**：强烈建议把 Repair 画到 `S2`（而不是停在 `R5`），读者会更容易接受“修复把对拉回原段 + 调整分隔符”。

**画图时**：建议 **R0→R1→R2→R3→R4→R5** 六帧；每帧只标一种操作（尾元交换、`0` 左移、客户过 `0` 迁移），避免一图挤满箭头。

### 2.3 OPC：顺序保持交叉（Order Preserving Crossover）

**一句话**：先分别取两父代的商家顺序 `order1/order2`，在随机融合点 `f` 处拼接、`unique(...,'stable')` 去重并 `setdiff` 补齐，使 `1..n` 齐全；再像 PPC 一样先顺写商家、再在右侧第一个 `0` 槽填客户；若融合结果与 `order1` 完全相同，代码会**随机交换两个商家**引入扰动。

**(A) 商家顺序到底怎么取（严格按源码 `SegmentBasedCrossover_extractMerchantOrder`）**

源码是两步：

1. **扫描提取（按出现顺序追加）**：从左到右扫整条染色体，只要遇到商家基因 `1..n` 就追加到 `order`。  
   - 对当前 `P2 = 【3】【7】【1】【5】【0】【4】【8】【2】【6】`：扫描到的商家依次是 `3 → 1 → 4 → 2`，所以扫描结束时

```text
scan_order(P2) = 【3】【1】【4】【2】
```

2. **去重（`unique(order)`）**：函数最后写的是 `order = unique(order);`。在 MATLAB 里**不加 `'stable'`** 的 `unique` 会返回**排序后的唯一值**（升序），因此：

```text
unique(scan_order(P2)) = 【1】【2】【3】【4】
```

所以“源码里用于 OPC 融合的 `order2`”会变成升序，而不是扫描顺序。

> 若想保留扫描顺序，应写 `unique(order,'stable')`；但本仓库当前实现确实是 `unique(order)`（会排序）。

因此本例中 `order1/order2`（供 OPC 融合）写作：

```text
O1 = 【1】【2】【3】【4】   （来自 P1）
O2 = 【1】【2】【3】【4】   （来自当前 P2：扫描序为 3,1,4,2；`unique` 后变升序）
```

**教学备注（画图建议，先把“扫描顺序”和“源码顺序”区分开）**

- **扫描顺序（直觉上的父代商家先后）**：`scan_order(P2)=【3】【1】【4】【2】`（只看 P2 里商家首次出现的顺序）
- **源码用于融合的顺序向量**：`order2 = unique(scan_order(P2)) = 【1】【2】【3】【4】`（因为 `unique` 默认排序，不保留先后）

所以：你如果要画“父代信息”，画 `scan_order(P2)`；你如果要画“OPC 代码里真正拿来做融合的向量”，画 `order2`。

**(B) 现状：按当前源码（`unique` 会排序）做融合，为什么会退化**

本例里 `order1` 也会变成 `【1】【2】【3】【4】`，因此无论融合点 \(f\) 取多少：

- `fused_order = [order1(1:f), order2(f+1:end)] = 【1】【2】【3】【4】`
- 去重、补齐后仍为 `【1】【2】【3】【4】`，与 `order1` 完全相同 → 触发“退化扰动”：**随机交换两个商家位置**

下面用**示例**取交换商家 `2` 与 `3`：

```text
F = 【1】【3】【2】【4】
```

## 5. 修补源码讲解：让 OPC 真正“顺序保持”（把 `unique` 改为 `'stable'`）

你现在看到的退化（`order1 ≈ order2 ≈ 【1】【2】…【n】`，然后只能靠“随机交换两个商家”制造差异），根因是：`SegmentBasedCrossover_extractMerchantOrder` 用了 **`unique(order)`**，MATLAB 默认会把结果**排序**，把父代的“出现先后”信息抹掉。

### 5.1 应该改哪里（最小改动）

文件：`PlatEMO/Algorithms/Multi-objective optimization/A-amos/SegmentBasedCrossover.m`  
函数：`SegmentBasedCrossover_extractMerchantOrder(individual, n)`

把最后一行从：

```matlab
order = unique(order);
```

改成（保序去重）：

```matlab
order = unique(order,'stable');
```

这样就会得到：

- `order2 == scan_order(P2)`（例如本例 `【3】【1】【4】【2】`）
- `order1 == scan_order(P1)`（例如若 P1 的商家出现顺序是 `【1】【2】【3】【4】`，就会保留它）

### 5.2 改完后，OPC 的融合会变成什么样（用本例说明）

以本文件当前 `P1`/`P2` 为例：

- `scan_order(P1)=【1】【2】【3】【4】`（P1 中商家出现顺序）
- `scan_order(P2)=【3】【1】【4】【2】`
- 修补后：`order1=【1】【2】【3】【4】`，`order2=【3】【1】【4】【2】`

若取融合点 `f=2`：

```text
fused_order = [order1(1:2), order2(3:4)]
           = [【1】【2】,     【4】【2】]
```

接着代码会做 `unique(...,'stable')`（它本来就写了 `'stable'`）去重，得到：

```text
F = 【1】【2】【4】
```

再做“补全缺失商家”（`setdiff` 结果按升序追加；这里缺 `3`）：

```text
F = 【1】【2】【4】【3】
```

这时 `F` 通常 **不再等于** `order1`，所以“随机交换两个商家”的退化扰动一般**不会触发**；OPC 才会真正体现“前缀来自父代 1、后缀来自父代 2”的顺序融合。

### 5.3 你画示意图时该怎么画（建议 3 行）

改完源码后，OPC 最直观的三行图是：

```text
order1（P1 扫描商家顺序）= 【...】
order2（P2 扫描商家顺序）= 【...】
融合点 f：F = 【...】（先拼接→去重保序→补全）
```

后续“写商家→0 槽插客户→Repair”仍按前文的 PPC/Repair 画法即可。


**(C) 插入客户（与 PPC 同一套规则；Repair 前）**

与 §2.2 相同：先写商家 `F`，再在每位商家右侧第一个 `0` 槽填客户。对 `F = 【1】【3】【2】【4】` 得到：

```text
O_OPC（填充后、Repair 前）= 【1】【3】【2】【4】【5】【7】【6】【8】【0】
```

（与当前 P2 下 PPC 的中间态相同，因 `sorted_merchants` 与这里的 `F` 一致；Repair 后两算子输出一般仍会再分化。）

> 画图提示：OPC 画“融合点切两段顺序向量 → 去重补齐 →（必要时）随机换位 → 再 0 槽插客户 → Repair”。

## 3. 变异算子（4 个）

下面用同一条染色体作为“操作前”，分别展示 T1–T4 的“操作后”。示例的“被选中基因/段”可在画图时用高亮框或箭头标出。

统一“操作前”取：

```text
X = 【1】【5】【2】【6】 0 【3】【7】【4】【8】
```

---

### 3.1 T1：商家 → 段首（实现为移到该段最前端）

**一句话**：在某一段内选中一个商家，把它从原位置剪切出来，插到该段段首（`0` 不动）。

**示例**：在第二段选中商家 `4`，移到第二段段首：

```text
前：X     = 【1】【5】【2】【6】 0 【3】【7】【4】【8】
后：O_T1  = 【1】【5】【2】【6】 0 【4】【3】【7】【8】
```

> 画图提示：画一个“剪切/移动”箭头：把 `【4】` 从第二段中间搬到第二段最左边；保持 0 位置不变。

---

### 3.2 T2：客户 → 段尾（实现为移到该段最后）

**一句话**：在某一段内选中一个客户，把它从原位置剪切出来，追加到该段段尾。

**示例**：在第二段选中客户 `7`，移到第二段末尾：

```text
前：X     = 【1】【5】【2】【6】 0 【3】【7】【4】【8】
后：O_T2  = 【1】【5】【2】【6】 0 【3】【4】【8】【7】
```

> 画图提示：把 `【7】` 从段内拿出来，放到该段最右端。

---

### 3.3 T3：滑动分隔符 0（只在“成对安全边界”移动）

**一句话**：把 `0` 向左或向右滑动，但只能落在“不会把某对 `(s,s+n)` 撕开到不同段”的边界处。

**示例（向右滑动）**：把 `0` 从 `【…】【6】 0 【3】…` 移到 `【…】【7】 0 【4】…`（表示把 `【3】【7】` 这对从第二段切换到第一段，或等价地说让分界线跨过它们）：

```text
前：X     = 【1】【5】【2】【6】 0 【3】【7】【4】【8】
后：O_T3  = 【1】【5】【2】【6】【3】【7】 0 【4】【8】
```

> 画图提示：用一个粗箭头画 `0` 的“滑动”，并强调它跨过的是**完整对**（这里跨过 `【3】【7】`），因此不会出现“商家在一段、客户跑到另一段”的非法情况。

---

### 3.4 T4：跨段迁移整对（剪切–粘贴一对商家+客户）

**一句话**：选中一对 `(s, s+n)`，从源段整体剪切出来，插到另一段某个位置，保持 `s` 紧邻 `s+n`（实现中也允许不紧邻但会修复）。

**示例**：把第二段中的整对 `【4】【8】` 剪切到第一段 `【2】【6】` 后面：

```text
前：X     = 【1】【5】【2】【6】 0 【3】【7】【4】【8】
后：O_T4  = 【1】【5】【2】【6】【4】【8】 0 【3】【7】
```

> 画图提示：T4 最适合画“整块移动”：把 `【4】【8】` 画成一个括号框住的块，箭头从第二段指向第一段插入点。

## 4. 统一后处理（图里可用一个“Repair”方框表示）

无论交叉或变异，实际运行里都会有修复流程（如 `OrderSegmentRepair`）来保证：

- `0` 的个数正确、首尾不为 0；
- 任意 `s` 在 `s+n` 之前；
- 尽量不跨段拆对、段长度合理。

画示意图时通常不必展开修复细节，只需在算子后接一个 **Repair** 框即可。
