# 调试指南：无效解诊断

## 已添加的调试功能

我已经在`planner_order_v3.m`中添加了详细的调试功能，会在每次计算完所有解后输出统计信息。

## 调试输出说明

### 1. 无效原因统计

调试输出会显示以下7类无效原因的数量：

1. **Inf/NaN**: 目标值计算中出现无穷大或非数字
2. **负数**: 目标值为负数
3. **缺少必需的点**: 解中缺少1到20中的某些点
4. **0分隔符数量错误**: 0分隔符数量不是2个（应该是m-1=2）
5. **空段**: 分段后某些段为空
6. **能量计算错误**: 能量计算过程中出现异常值
7. **时间计算错误**: 时间计算过程中出现异常值

### 2. 无效解示例

调试输出会显示前3个无效解的详细信息，包括：
- 无效类型
- 路径信息
- 缺失的点（如果有）
- 0分隔符数量（如果错误）
- E_all和T_all数组
- 原始目标值
- 惩罚值

## 如何使用调试信息

### 步骤1：运行优化

运行优化算法，观察控制台输出的调试统计信息。

### 步骤2：分析主要无效原因

查看"无效原因统计"部分，找出数量最多的无效原因类型。例如：
- 如果"缺少必需的点"数量最多 → 说明交叉/变异操作破坏了解的完整性
- 如果"能量计算错误"数量最多 → 说明能量计算公式中有数值异常
- 如果"空段"数量最多 → 说明分段逻辑有问题

### 步骤3：查看无效解示例

查看"无效解示例"部分，了解具体的无效解是什么样的：
- 查看路径结构
- 查看缺失的点
- 查看E_all和T_all的值

### 步骤4：针对性修复

根据主要无效原因，进行针对性修复：

#### 如果主要是"缺少必需的点"
- 检查`EnsureSolutionCompleteness`函数是否被正确调用
- 检查交叉和变异操作是否破坏了解的完整性
- 增加修复概率或强制修复

#### 如果主要是"能量计算错误"
- 检查`load_kg`、`UAV_w`、`v_0`等参数是否异常
- 检查`d_hor`（距离矩阵）是否有效
- 检查能量计算公式中的开方运算

#### 如果主要是"时间计算错误"
- 检查`v_u`、`v_h`、`v_d`是否为零或异常
- 检查时间累加过程

#### 如果主要是"空段"
- 检查分段逻辑
- 检查0分隔符的处理

## 下一步行动

根据调试输出，确定主要无效原因后，可以：
1. 修改相应的修复函数
2. 调整算法参数
3. 改进交叉和变异操作
4. 修复数值计算问题
