# 消融实验现象分析：为何去掉自适应/聚类后 HV 反而更好

## 聚类在算法中的角色（说明）

当前**聚类只用于逼近目标空间的流形结构**，供**父代选择**使用（邻域 + 每类代表的 globalClust）。  
**环境选择（EnvironmentalSelection）里没有用聚类**：选谁完全由非支配排序 + 超体积/拥挤距离决定；选择完成后才对选中解重新做一次目标空间聚类，更新 clustTag/clustName/centroid，供下一代的父代选择用。

---

## 现象

- **ablation_AMOA**（完整 A_amos）：30 次平均 HV 最低，Pareto 前沿最差（更远离原点）。
- **ablation_A_amos_noAdapt**（去掉自适应）：HV 与前沿均优于完整版。
- **ablation_A_amos_noCluster**（去掉聚类）：HV 与前沿最好。

即：在当前订单分配问题上，**完整算法的两个核心机制（自适应参数 + 目标空间聚类）都在拖累性能**。

---

## 原因分析

### 1. 聚类（Clustering）为何会变差

在完整版 A_amos 中：

- 对目标空间做聚类，得到若干类（最多 Kmax，如 20）。
- **父代选择**时：
  - **全局池** `globalClust` 只从**每个聚类取 f1 最小、f2 最小的解**（至多 2 个/类），因此全局池大小 ≈ 2×聚类数（约 40），而不是种群大小（如 300）。
  - 以概率 `localSearchProb` 从**当前个体所在聚类的邻域**选父代，否则从 `globalClust` 中选。

带来的问题：

- **父代多样性被严重压缩**：真正参与交叉的“全局”父代只有约 20 个代表，探索空间小，容易早熟收敛。
- **邻域内选父代**进一步强化“局部相似个体”之间的交叉，不利于在目标空间上均匀覆盖 Pareto 前沿。
- noCluster 版本把 `globalClust = pop`（全种群），父代从 300 个解里选，探索能力强得多，因此 HV 和前沿都更好。

结论：**当前“每类一个代表 + 邻域内选父代”的聚类用法，在本问题上限制了探索，是性能变差的主要原因之一。**

#### 为什么直觉上「从聚类找父代 → 沿前沿完整分布」会成立？当前实现为何相反？

直觉成立的前提是：**父代池里本来就保留了“沿前沿完整分布”的候选**。例如：若每个聚类对应前沿上的一段，且父代从“各聚类中**有代表地**选”，那确实更容易维持沿前沿的分布。

但在当前实现里，聚类被用成了**对父代池的压缩**，而不是对分布的保留：

1. **全局池不是“沿前沿的完整分布”，而是“每类至多 2 个代表”**  
   即便已改为每类取 f1 最小、f2 最小（共约 2×聚类数，约 40 个），**其余同簇解都不再能作为“全局”父代**。种群有 300 个解、本可沿前沿分布，但真正参与“全局父代”的只有这 40 个。也就是说：**沿前沿的完整分布被压缩成 40 个点**，大部分解根本不会被选为父代，所以不是“更容易拿到完整分布”，而是**主动丢掉了大部分分布**。

2. **邻域内选父代 = 只在“同一小段前沿”内交叉**  
   以概率从当前个体所在聚类的邻域选父代，等价于只在同一段前沿内做交叉。这对**局部打磨**有利，但对**沿整条前沿的覆盖**不利：不同段之间的重组变少，难以在全局上维持均匀分布，更容易在少数几段上收敛。

3. **若要“用聚类拿到完整分布”，更合理的用法应是**  
   - **父代池仍用全种群**（或足够大的子集），保留沿前沿的完整候选；  
   - 聚类只用来**引导选谁**（例如：倾向从不同簇选父代以促进分布），而不是把父代池缩小到每类 1～2 个代表。  
   当前做法是后者（缩小父代池），所以效果与“沿前沿完整分布”的直觉相反。

总结：**不是“聚类本身”有害，而是“用聚类把父代池压成每类 1～2 个代表”有害**——这会把本可沿前沿分布的 300 个解压缩成约 40 个代表，反而更难拿到完整分布，因此加了聚类后反而不如不加。

#### 两个细节澄清

**Q1：从当前聚类里选父代，有没有可能选到自己？**  
**不会。** 代码里在从邻域选父代之前，会先把当前个体从该聚类的邻域里删掉（`neighborhood(loc,:)=[]`），所以参与“局部”抽样的只有**同簇的其他个体**，不会选到自己。只有当既不走“邻域”也不走“全局”（例如全局池为空）时才会走备用分支 `parent = currentSol`，一般不会发生。

**Q2：从「每类 f1/f2 最小组成的全局池」里选一个解，会不会导致很多个体选到同一个父代？**  
**会。** 全局池大小约 2×聚类数（约 40），种群大小 300。每个个体独立地 `randsample(globalSize, 1)` 从这 40 个里抽一个，是**有放回抽样**，所以平均每个代表会被抽中约 300/40 ≈ 7.5 次/代。也就是说，很多个体会重复选到同一个父代，父代多样性被进一步压缩，也是“加聚类后反而不如不加”的原因之一。

### 2. 自适应（Adaptation）为何会变差

在完整版中，基于 HV 的停滞检测会：

- 若最近 20 代 HV 增长 < 1%，则判定停滞，并：
  - 提高变异概率：`adaptivePm` 升高（上限 0.9）；
  - 降低交叉概率：`adaptivePc` 降低（下限 0.4）；
  - 提高“大步长”变异比例 `explorationRate`；
  - 停滞时还降低局部搜索倾向（`adjustedBeta = BETA*0.5`）。

可能的问题：

- **停滞判定过敏感**：订单分配问题上 HV 曲线可能本身增长较慢或波动，20 代、1% 的阈值容易误判为“停滞”，从而频繁触发强探索。
- **参数调整方向在本问题上不合适**：例如 Pm 升得过高会破坏已有好解，Pc 降得过低会减少优良模式的传递，整体收敛变差。
- noAdapt 使用**固定** pc/pm，搜索更稳定，反而得到更好的 HV 和前沿。

结论：**在当前问题与参数下，这套“HV 停滞 → 提 Pm、降 Pc”的自适应策略是在帮倒忙。**

#### 自适应算子失效原因分析（细化）

**1. 自适应机制在做什么**

- **触发条件**：① 最近 40 代 HV 增长 &lt; 2.5% → 判停滞，`stagnationCounter += 1`；② 最近 10 代多样性（目标空间 std 归一化）&lt; 0.01 → 判多样性过低。
- **响应动作**：  
  - 提高变异概率 `adaptivePm`（上限 0.5）、降低交叉概率 `adaptivePc`（下限 0.6）；  
  - 提高 `explorationRate`（T4 大步长变异比例，上限 0.7）；  
  - `stagnationCounter > 3` 时降低局部搜索倾向（`adjustedBeta = BETA*0.5`）；  
  - `stagnationCounter > 2` 时以 0.4 概率做段交换；每 10 代以 0.2 概率额外一次变异。

**2. 为何在本问题（订单分配/段结构）上容易失效**

| 原因 | 说明 |
|------|------|
| **交叉对本问题更重要** | 段式编码下，交叉能保留“某几段已优”的块结构，在个体间重组。停滞时**降 Pc、升 Pm** 等于少做块重组、多做单点/段内扰动，优良段结构难以在种群内传播，收敛变慢或变差。 |
| **停滞判定的时间窗与阈值不匹配** | 中后期 HV 常会长期平台期（在补前沿缺口），40 代、2.5% 仍可能频繁判“停滞”。一旦误判，就长期处于“高 Pm、低 Pc”状态，相当于在**本应细调收敛的阶段**反而加大扰动、减少重组。 |
| **T4 大步长变异过于破坏** | T4 是跨段迁移整段，改动大。停滞时提高 `explorationRate` 会更多触发 T4，容易破坏已形成的段分配结构，产生大量劣解或需修复解，HV 不升反降。 |
| **负反馈环** | 判停滞 → Pm↑、Pc↓、T4↑ → 子代质量变差、HV 波动或下降 → 下一窗仍“增长不足” → `stagnationCounter` 继续升 → 参数更激进，更难恢复。 |
| **多样性指标易误触** | `diversity = mean(std(validObj))/(mean(mean(validObj))+1e-10)`，目标值量级在 1e6 时比值很小。即便前沿已铺开，也可能被判“多样性过低”，进一步推高 Pm、压低 Pc。 |
| **恢复慢** | 只有“最近 40 代增长 ≥ 2.5%”时 `stagnationCounter` 才减 1。若已累加到 5～10，要很多代连续改善才能复位，算法会长时间停留在“强探索、弱交叉”模式，不利于收敛。 |

**3. 小结**

自适应本意是“停滞时多探索、少收敛”，但在本问题中：① 停滞常被**误判**（平台期≠真停滞）；② 响应方向**与本问题需求相反**（应保持或加强交叉以传播段结构，却加强了破坏性更大的变异）；③ 易形成**负反馈**且**恢复慢**。因此 noAdapt（固定 Pm/Pc、固定 explorationRate）反而更稳、平均 HV 更好。若希望保留自适应，需从“触发更保守、响应更温和、或改为停滞时略升 Pc 而非降 Pc”等方向重设计。

### 3. 两者叠加

- 完整版 = **小父代池（聚类） + 易误触发的自适应**，既限制探索又可能错误地加大扰动，因此表现最差。
- noAdapt：去掉自适应，参数稳定，但聚类仍在，父代池仍小，所以优于完整版、但通常不如 noCluster。
- noCluster：父代来自全种群，探索充分；若自适应在本问题上触发不频繁或影响较小，则可能仍能取得更好结果。

这与您图中“noCluster 略优于 noAdapt、两者都明显优于完整版”的现象一致。

## 基于 ablation01 三组实验的现象与原因（“仍不行”）

在 ablation01_A_amos / noCluster / noAdapt 的对比中可以看到：

### 现象小结

1. **左图（HV 排名第 1 的那次—目标值）**  
   - **ablation01_A_amos（蓝）**：单次最好 run 的 Pareto 前沿**最宽**，在 f1–f2 空间覆盖范围大。  
   - **noCluster / noAdapt（红、黄）**：单次最好 run 的前沿更集中在左下角，分布更窄但 f1、f2 数值更优。

2. **右图（30 次平均 HV）**  
   - **ablation01_A_amos（蓝）**：**平均 HV 最低**，整条曲线都在下面。  
   - **noCluster（红）**：平均 HV 最高。  
   - **noAdapt（黄）**：介于两者之间，明显高于完整版。

即：**完整版在“最好的一次”里能跑出最宽的前沿，但 30 次平均 HV 最差。**

### 可能原因归纳

1. **方差大、稳定性差**  
   完整版有时能跑出很宽、很好的前沿（所以左图蓝点覆盖大），但更多 run 表现一般或较差，导致 30 次平均被拉低。聚类 + 自适应可能放大对初值/随机性的敏感度，使不同 run 之间差异变大。

2. **聚类仍限制“平均表现”**  
   即便已改为每类取 f1 最小 + f2 最小，全局池大小仍约为 2×聚类数，远小于种群规模。多数 run 下，父代多样性不足仍可能导致平均收敛变差；只有少数 run 随机性恰好有利时才能出现左图那种宽前沿。

3. **自适应仍在对平均表现不利**  
   温和化后（40 代、2.5%、Pm≤0.5、Pc≥0.6）若完整版平均 HV 仍低于 noAdapt，说明在当前问题上，**任何程度的“停滞就调参”**都可能降低平均表现，或与聚类叠加后负面效果更明显。

4. **“最宽前沿”与“平均 HV”目标不完全一致**  
   平均 HV 更看重 30 次都稳定地靠近真实前沿并覆盖得好；完整版可能偏向少数几次跑出很宽但未必 HV 最高的前沿，导致平均 HV 仍不如更稳的 noCluster/noAdapt。

### 建议：先跑数据诊断脚本

在 `Order_EXP_Function` 下已提供 **`analyze_ablation_summary.m`**，会读取三组实验的 `*_summary.xlsx`，输出：

- 30 次 HV_end / IGD_end 的 Mean、Std、Min、Max；  
- 最后一代 30 次平均 HV 及标准差；  
- 每代 30 次 HV 的标准差（代 1 / 中间 / 末代），用于看**收敛过程是否更不稳**。

运行方式：在脚本里填好 `expNames = {'ablation01_A_amos','ablation01_A_amos_noCluster','ablation01_A_amos_noAdapt'}` 后 F5，或命令窗口调用 `analyze_ablation_summary(expNames)`。  
若完整版的 HV_end 标准差明显大于 noCluster/noAdapt，即可佐证“方差大、稳定性差”的解释；再结合文档中的方案（进一步弱化聚类/自适应或直接以 noCluster 为基线）做后续改动。

## 既能保持聚类又能使消融符合预期的改法

目标：**保留“目标空间聚类 + 流形/邻域”结构**，但去掉“父代池过小、多人重复选同一父代”的副作用，使带聚类的完整版在消融里不劣于 noCluster/noAdapt。

核心原则：**聚类只用来“引导选谁”（或“在哪儿选”），不用来“把父代池缩小成几十个代表”。**

---

### 改法 1：全局用全种群，局部仍用聚类（推荐，改动最小）

- **全局父代**：不再从「每类 f1/f2 最小」组成的小池里抽，改为**直接从全种群 `pop` 里随机选**（与 noCluster 的全局一致），父代池 = 300，不会多人抢同一批代表。
- **局部父代**：保持现状——以 `localSearchProb` 从**当前个体所在聚类的邻域**（已排除自己）里选一个。这样聚类仍然在起作用：同簇内交叉、流形局部求精。

**效果**：保留“邻域内选父代”的聚类用法，去掉“全局池压缩”；实现上只需在构建完 `globalClust` 后加一行 `globalClust = pop; globalSize = size(pop,1);`（或直接让“全局”分支从 `pop` 抽样），其余逻辑不变。消融时若完整版 ≥ noCluster，说明问题确实在全局池过小。

---

### 改法 2：大幅扩大全局池，仍按类取代表

- 不把全局池压成每类 2 个，而是**每类取多个人**：例如每类内按 f1 排序取前 k 个、按 f2 排序取前 k 个（k=3~5），或每类取 min(类内个数, sqrt(类内个数)) 个代表，使全局池达到约 100–200。
- 这样从全局池抽父代时，重复选到同一人的概率明显下降，同时仍保留“按类代表”的分布感。

适合希望**显式保留“每类代表”**、又不想用全种群的折中方案。

---

### 改法 3：全局池仍为每类代表，但限制“被选次数”或按多样性选

- 全局池仍由每类 f1/f2 最小等组成（约 40 个），但在**为 300 个个体分配父代时**，对每个代表限制“最多被选几次”（例如 ceil(300/40)），或优先选“当前代被选次数较少”的代表，使 40 个代表被用得更均匀。
- 实现比改法 1 复杂，但能保留“小全局池 + 聚类代表”的结构，同时缓解“很多人选到同一个父代”的问题。

---

### 改法 4：分阶段——前期大池、后期再用聚类小池

- 前若干代（如 0–maxgen/2）：`globalClust = pop`，全局从全种群选，探索充分。
- 后若干代：再启用“每类 f1/f2 最小”组成的小全局池 + 邻域内选，用聚类做收敛与分布。

这样前期避免聚类压缩探索，后期保留聚类做流形求精；消融时若完整版能追上或略超 noCluster，说明分阶段有效。

---

**建议优先试改法 1**：实现简单、与现有消融逻辑一致，且能直接验证“保留聚类但全局池=全种群”是否足以让消融符合预期；若可以，再考虑是否加改法 2/3/4 做进一步微调。

## 解决方案建议

### 方案一：弱化聚类对父代选择的限制（优先尝试）

**思路**：保留聚类用于流形逼近（父代选择中的邻域结构），但**父代选择不要只从“每类一个代表”里选**。

- **做法 1**：父代选择的“全局池”改为全种群，即与 noCluster 一致：
  - 在 A_amos.m 中，将构建 `globalClust` 的循环改为直接把 `globalClust = pop`（或从 pop 中随机采样一个较大子集），不再用“每类一个代表”。
- **做法 2**：若仍想用聚类，则**扩大全局代表集**：
  - 每个聚类内取多个代表（例如 min(类内个数, 3) 或 sqrt(类内个数)），使 `globalClust` 大小接近 50–100 或更多，而不是约 20。
- **做法 3**：降低“局部搜索”概率，让更多父代来自全局：
  - 减小 `BETA`（例如从 0.8 调到 0.3–0.5），或把 `localSearchProb` 的随代数增长改得更平缓，使多数代数仍从全局池选父代。

这样既保留聚类结构（流形/邻域仍可用于父代选择），又避免父代池过小导致的早熟收敛。

### 方案二：放宽或关闭停滞检测与自适应

**思路**：避免误判停滞和过度调整 pc/pm。

- **做法 1**：**直接关闭自适应**，使用固定 pc、pm（即沿用 noAdapt 的写法），作为新的“默认”配置。
- **做法 2**：若希望保留自适应，则**放宽触发条件**：
  - 停滞窗口从 20 代改为 30–50 代；
  - HV 增长阈值从 1% 改为 2%–3%；
  - 调整幅度更温和：例如 `adaptivePm` 上限改为 0.5，`adaptivePc` 下限改为 0.6，避免剧烈改变搜索行为。
- **做法 3**：**分阶段**：前 50% 代数不启用自适应（或只用固定参数），后半段再根据 HV 趋势轻微调整。

### 方案三：分阶段策略（聚类 + 探索/收敛分离）

**思路**：前期强调探索（大父代池），后期再强调聚类与局部搜索。

- 前若干代（如 0–maxgen/2）：`globalClust = pop`，父代从全种群选（等价于 noCluster 的父代选择），或大幅降低 `localSearchProb`。
- 后若干代：再启用“每类代表 + 邻域”的父代选择，或提高 `localSearchProb`，用于收敛与分布均匀化。

这样既避免早期因聚类导致的探索不足，又保留后期用聚类做分布与收敛的潜力。

### 方案四：以 noCluster 为基线，再谨慎加回聚类或自适应

**思路**：当前 noCluster 效果最好，可将其设为基线，再小步加回一个机制并做消融。

- 先**仅在 noCluster 上**做参数调优（pc、pm、BETA、maxgen 等），得到稳定基线。
- 再**只加回聚类**：父代池仍用全种群（`globalClust = pop`）；聚类仅用于流形/邻域结构（环境选择里不用聚类决定选谁）。观察 HV 与前沿是否仍能保持或提升。
- 若加回聚类后仍无损失，再考虑**轻量自适应**（更宽松的停滞条件、更小的 pc/pm 调整幅度），并逐项做消融验证。

---

## 建议实施顺序

1. **先做方案一**：在 A_amos.m 中把父代选择的“全局池”改为全种群（或每类多代表），其余逻辑不变，跑同样的消融实验，看 HV 与前沿是否明显接近或超过 noCluster。
2. **若仍不如 noCluster**：再按方案二放宽或关闭自适应，或直接采用 noAdapt 的固定参数。
3. **若希望保留聚类/自适应的设计意图**：再按方案三做分阶段，或按方案四以 noCluster 为基线逐步加回并验证。

这样可以在不改变算法整体框架的前提下，有针对性地消除“父代池过小”和“自适应误触发”两个主要负面因素，并保留聚类/自适应在其它问题或参数下的潜在价值。
